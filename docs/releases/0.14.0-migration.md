# Migrating to rappct 0.14.0

Version 0.14.0 is the first release candidate after published version 0.13.3.
The intermediate 0.13.4 through 0.13.10 manifest versions were never published.
Because rappct is pre-1.0, this minor release includes intentional API and
behavior corrections alongside additive features.

## Required source migrations

- Prefer `CapabilityName` over its compatibility alias `KnownCapability`.
  Both names still work, but exhaustive matches need a wildcard because the
  capability enum is non-exhaustive and has new variants.
- Add fallback arms when matching `AcError` or `ResourcePath`; both have new
  variants.
- Construct `LaunchOptions` with builders or `..Default::default()` instead of
  complete struct literals.
- Replace removed `util::{OwnedHandle, LocalFreeGuard, FreeSidGuard}` uses with
  standard owned handles or the corresponding `windows` crate ownership APIs.
  The internal `rappct::ffi` module is deliberately not public.
- Replace `LoopbackExemptionGuard::new(sid)` with
  `LoopbackExemptionGuard::new_confirmed(LoopbackAdd::new(sid).confirm_debug_only())`.
  Confirmation is stored in the request value and consumed by the add operation.
- `launch_in_container` now rejects `StdioConfig::Pipe`; use
  `launch_in_container_with_io` so pipe ownership remains observable.
- `Launched` now owns process and job resources and exposes `wait`, `resume`,
  and `terminate`. Resource ownership means it is no longer `Copy`, `Clone`,
  `PartialEq`, or `Eq`, and it can no longer be constructed directly.
- Use `LaunchedIo::capture_output` to drain stdout and stderr concurrently.
- Use `AppContainerProfile::open()` when a profile is expected to exist.
  `ensure()` no longer treats invalid profile metadata as an existing profile.

## Security behavior

The unpublished `_test_helpers` feature and public hidden `test_support` module
were removed. LPAC support and launch environment or working-directory behavior
can no longer be changed by `RAPPCT_TEST_*` environment variables in downstream
`--all-features` builds.

## Verification baseline

The compatibility baseline is tag `rappct-v0.13.3` at commit
`427287c3f5f018d52c2711313792006fcc00d845`. Release preparation accepts both
legacy `rappct-vX.Y.Z` and current `vX.Y.Z` tags, selecting the highest reachable
semantic version below the target. Run:

```powershell
just test-release-flow
just api-compat
just release-surface
cargo test --test api_surface --all-features --locked
cargo package --locked
```

`just api-compat` requires `cargo-semver-checks` 0.49.0. It accepts only the
eight reviewed break classes described above and fails if the API delta changes.
